### Внесені зміни у вихідну логіку моделі, за варіантом:

**1. Додано механіку зникнення агентів (`check-survival`)**  
Згідно з варіантом завдання, було реалізовано ймовірність зникнення агента на кожному такті модельного часу. Ризик зникнення залежить від двох факторів: кількості «чужих» агентів (іншого кольору) у безпосередньому оточенні агента та кількості представників *їхньої* власної групи поруч із кожним із них (`similar-nearby`).

Для регулювання інтенсивності конфліктів на інтерфейс додано керуючий слайдер **aggression** (діапазон від `0.0` до `5.0`, крок `0.5`, значення за замовчуванням `0.5`). Нова процедура перевірки виживання виглядає наступним чином:

```netlogo
to check-survival
  ask turtles [
    ;; знаходимо всіх сусідів іншого кольору ("чужих")
    let enemies (turtles-on neighbors) with [ color != [color] of myself ]
    if any? enemies [
      ;; тиск залежить від кількості "чужих" та кількості "своїх" у їхньому власному оточенні
      let pressure sum [ 1 + similar-nearby ] of enemies
      ;; обчислюємо ймовірність зникнення (у відсотках), масштабовану повзунком aggression
      let death-chance pressure * aggression
      if random-float 100 < death-chance [
        die
      ]
    ]
  ]
end
```

**2. Оновлено основний цикл симуляції (`go`) та розрахунок глобальних показників (`update-globals`)**  
У процедуру `go` додано виклик `check-survival` після переміщення незадоволених агентів, а також повторний перерахунок стану агентів і перевірку умови зупинки на випадок повного зникнення популяції (`not any? turtles`):

```netlogo
to go
  if not any? turtles or all? turtles [happy?] [ stop ]
  move-unhappy-turtles
  update-turtles
  check-survival
  update-turtles
  update-globals
  tick
end
```

У процедурі `update-globals` додано захист від ділення на нуль, якщо на полі не залишиться агентів або жоден агент не матиме сусідів:

```netlogo
to update-globals
  let similar-neighbors sum [similar-nearby] of turtles
  let total-neighbors sum [total-nearby] of turtles
  ifelse total-neighbors > 0 [
    set percent-similar (similar-neighbors / total-neighbors) * 100
  ] [
    set percent-similar 0
  ]
  ifelse any? turtles [
    set percent-unhappy (count turtles with [not happy?]) / (count turtles) * 100
  ] [
    set percent-unhappy 0
  ]
end
```

**3. Додано графік зміни розміру популяції (`Population`)**  
На інтерфейс моделі додано новий елемент типу **Plot** з назвою `Population`, який на кожному такті модельного часу відображає поточну кількість активних агентів на полі за допомогою команди `plot count turtles`.

### Внесені зміни у вихідну логіку моделі, на власний розсуд:

**Реалізовано «розумний переїзд» агентів (виправлення недоліку базової моделі)**  
У першій лабораторній роботі було виявлено суттєвий недолік вихідної моделі - «сліпий» пошук нового місця (`find-new-spot`), коли незадоволений агент просто стрибав на випадкову вільну клітинку без оцінки нового оточення.

Логіку процедури `find-new-spot` було змінено: тепер незадоволений агент знаходить вільні клітинки в радіусі 10 клітинок (або по всьому полю, якщо поруч немає вільних місць), обирає до 5 випадкових кандидатів та оцінює кожен із них за функцією корисності - різницею між кількістю «своїх» і «чужих» сусідів. Після цього агент переміщується на найкращу з доступних клітинок:

```netlogo
to find-new-spot
  let my-color color
  ;; знаходимо всі вільні клітинки в радіусі 10
  let empty-spots (patches in-radius 10) with [ not any? turtles-here ]

  ;; якщо в радіусі 10 усе зайнято, шукаємо по всьому полю
  if not any? empty-spots [
    set empty-spots patches with [ not any? turtles-here ]
  ]

  ;; якщо вільні клітинки є, оцінюємо до 5 випадкових кандидатів і переїжджаємо на найкращу
  if any? empty-spots [
    let candidates n-of (min (list 5 count empty-spots)) empty-spots
    let best-spot max-one-of candidates [
      (count (turtles-on neighbors) with [ color = my-color ]) -
      (count (turtles-on neighbors) with [ color != my-color ])
    ]
    move-to best-spot
  ]
end
```

Така модифікація робить поведінку агентів більш реалістичною та напряму взаємодіє з новою механікою виживання: агенти цілеспрямовано уникають скупчень «чужих» і швидше формують безпечні однорідні кластери.

## Обчислювальні експерименти

### 1. Вплив рівня агресії на кінцевий розмір популяції

Досліджується залежність кінцевої кількості агентів, що вижили після стабілізації системи, від значення нового керуючого параметра `aggression`. Експеримент проводиться для значень `aggression` від 1 до 5 із кроком 1 (усього 5 прогонів). Інші керуючі параметри зафіксовані на базових значеннях:

* **number**: 2000
* **%-similar-wanted**: 30%
* **number-of-ethnicities**: 3

| Рівень агресії (`aggression`) | Кінцевий розмір популяції (`Population`) |
| --- | --- |
| 1 | 1238 |
| 2 | 1048 |
| 3 | 938 |
| 4 | 891 |
| 5 | 848 |

<img width="752" height="452" alt="image" src="https://github.com/user-attachments/assets/3ba68b84-a3dc-402f-b6bb-6299007bf5f9" />

**Висновок до експерименту:**  
Спостерігається чітка зворотна нелінійна залежність між рівнем агресії та кінцевим розміром популяції. Вже при `aggression = 1` популяція скорочується з початкових 2000 до 1238 агентів (втрата 38,1%), а при максимальному значенні `aggression = 5` - до 848 агентів (втрата 57,6%).

Водночас темп зменшення популяції помітно сповільнюється зі зростанням параметра (перехід від 1 до 2 зменшує популяцію на 190 агентів, тоді як від 4 до 5 — лише на 43 агенти), і повного вимирання не відбувається. Це пояснюється двома факторами: по-перше, механізм «розумного переїзду» допомагає агентам швидко знаходити однорідні групи та уникати ворожого оточення; по-друге, зникнення агентів на межах зіткнення різних груп створює порожні клітинки — своєрідні буферні зони, які ізолюють сформовані кластери один від одного та припиняють подальші втрати.
